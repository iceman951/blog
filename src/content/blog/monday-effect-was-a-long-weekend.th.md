สวัสดีครับ คราวนี้เปลี่ยนแนวไปทางการเงิน แต่เป็นความผิดพลาดแบบเดิมเป๊ะกับที่เคยเจอในบทความ benchmark — และคราวนี้ผมพลาดซ้ำเองในเวอร์ชันแรกของโพสต์นี้ด้วย

ถ้าเราซื้อหุ้นตัวเดิมจำนวนเงินเท่ากันทุกสัปดาห์ ยังไงก็ต้องเลือกสักวัน แล้วมักมีคนแนะนำวันจันทร์โดยอ้าง anomaly ในตำราการเงินที่เรียกว่า weekend effect ผมเลยลองรัน regression บนข้อมูลรายวันสิบปีของหุ้น 8 ตัวที่คนดูกันจริง โดยตั้งใจจะเขียนโพสต์สั้น ๆ ว่า effect นี้ตายไปนานแล้ว

ผลไม่ได้ออกมาแบบนั้นครับ รอบแรกเจอรูปแบบที่รอดการทดสอบแบบ family-wise จากนั้นเวอร์ชันแรกของโพสต์นี้ก็อธิบายรูปแบบนั้นทิ้งไปว่าเป็นผลข้างเคียงของปฏิทิน — ผลตอบแทนวันจันทร์คร่อมสามวัน วันอื่นคร่อมวันเดียว — แล้วตั้งชื่อโพสต์ตามนั้น พอมีคนตรวจสถิติอย่างจริงจังก็พบว่าคำอธิบายนั้นผมไม่เคยทดสอบจริง การทดสอบที่ผมพิงอยู่พังสามจุดแยกกัน และการเทียบ DCA ก็ไม่ยุติธรรม นี่คือฉบับเขียนใหม่ ตัวเลขทั้งหมดสร้างใหม่ โค้ดมี test แล้ว และข้อสรุปเล็กลงกว่าตอนเริ่ม

**ทั้งหมดนี้ไม่ใช่คำแนะนำการลงทุน** ผมไม่ใช่ที่ปรึกษาการลงทุนที่มีใบอนุญาต และข้อสรุปเชิงปฏิบัติข้างล่างคือการเลือกวันแทบไม่มีผลอยู่แล้ว นี่เป็น exploratory analysis บนหุ้น 8 ตัวที่ผมเลือกเพราะมันดังในปี 2026 และตัวเลขทุกตัวในนี้อยู่ภายใต้เงื่อนไขนั้น

## สรุปก่อน เผื่อยังไม่อยากอ่านยาว

- ค่าเฉลี่ยดิบ วันจันทร์เป็นวันที่ดีที่สุดของหุ้น **3 จาก 8 ตัว** (NVDA, TSLA, AMD) ไม่ใช่ "ส่วนใหญ่" อย่างที่เคยเขียน
- Bonferroni ใช้ได้แม้หุ้นจะสัมพันธ์กัน (มันแค่ conservative ขึ้น) และมีสัมประสิทธิ์เดียวที่ผ่านทั้ง Bonferroni และ Holm: **TSLA พฤหัส−จันทร์ −87 bps, p < 0.001**
- permutation test เดิมพังสามจุด รวมถึง PRNG ที่ผมเขียนเองซึ่งวนซ้ำทุก 10,466 ค่า แทนที่ด้วย dependent wild bootstrap ได้ family-wise **p = 0.0014** (Monte Carlo SE 0.0005)
- ตัวคุมวันปฏิทินมี collinearity กับ dummy วันจันทร์ (R² = 0.76) มันทำให้ SE โตสองเท่า ไม่ได้ทำให้ค่าประมาณเล็กลง — TSLA ลดแค่ราว 10%
- **ราคาเปิดค้านเรื่องเล่าเรื่องปฏิทิน**: ผลตอบแทนส่วนเกินของวันจันทร์อยู่ในช่วงเปิด→ปิดของวันจันทร์ทั้ง 8 ตัว ไม่ได้อยู่ในช่วงข้ามสุดสัปดาห์ ซึ่งเป็นช่วงข้ามคืนที่ *ต่ำสุด* ของสัปดาห์สำหรับ 6 ใน 8 ตัว
- DCA แบบยุติธรรม: การเลือกวันต่างกัน **ไม่ถึง 1% ของมูลค่าปลายทาง** และวันจันทร์ชนะทั้ง 8 ตัวเพราะ drift ล้วน ๆ ส่วนสัปดาห์ที่เริ่มมีผลมากกว่านั้นหลายสิบถึงหลายร้อยเท่า ในตัวอย่างนี้

## วัดอะไรบ้าง

หุ้น 8 ตัว — NVDA, TSLA, AAPL, MSFT, AMZN, META, GOOGL, AMD — **2,512 วันทำการ** ตั้งแต่ 14 ก.ย. 2016 ถึง 11 ก.ย. 2026 ใช้ราคาเปิดและราคาปิดที่ปรับ split แล้วจาก public historical endpoint ของ Nasdaq ส่วน market ใช้ระดับดัชนี S&P 500 จาก FRED คำว่า "หุ้นเทค" เป็นคำเรียกอย่างไม่เป็นทางการ: ทั้งแปดตัวอยู่ในสาม GICS sector (Information Technology, Consumer Discretionary, Communication Services) สิ่งที่มีร่วมกันคือเป็นบริษัทเทคโนโลยี/เติบโตขนาดใหญ่ของสหรัฐที่ทำผลงานได้ดีมาก

สมการเป็นแบบมาตรฐาน ใช้ log return รายวัน และให้วันจันทร์เป็นฐาน:

```
r_t = α + β·r_market,t + γ_Tue·D_Tue + γ_Wed·D_Wed + γ_Thu·D_Thu + γ_Fri·D_Fri + ε_t
```

γ แต่ละตัวตอบว่า "หุ้นตัวนี้ให้ผลตอบแทนในวันนั้นมากหรือน้อยกว่าวันจันทร์เท่าไหร่ หลังหักสิ่งที่ตลาดทำในวันเดียวกันออกไปแล้ว" ค่า standard error ใช้ Newey-West 8 lag เพราะผลตอบแทนรายวันมี heteroskedasticity และ autocorrelation อ่อน ๆ ถ้าใช้ค่ามาตรฐานธรรมดาจะอ้างความแม่นยำเกินกว่าที่ข้อมูลมี

## รอบแรกดูแรงมาก

ค่าเฉลี่ยแบบไม่คุมอะไรเลย วันจันทร์เป็นวัน*ที่ดีที่สุด*ของหุ้นสามจากแปดตัว — NVDA, TSLA และ AMD — ซึ่งก็ตรงข้ามกับ weekend effect ในตำราอยู่แล้ว:

| | จันทร์ | อังคาร | พุธ | พฤหัส | ศุกร์ |
| --- | ---: | ---: | ---: | ---: | ---: |
| NVDA | 30.8 | 21.8 | 30.0 | 19.6 | −2.4 |
| TSLA | 66.9 | 18.7 | 20.9 | −33.3 | −3.3 |
| AMD | 56.3 | 15.4 | 21.5 | −3.6 | 2.7 |
| AAPL | 19.0 | 16.8 | 21.1 | −7.4 | 0.7 |

<p class="affiliate-note">ค่าเฉลี่ย log return หน่วยเป็น basis point ต่อวันทำการ อีกสี่ตัวที่เหลือ วันจันทร์อยู่อันดับสองหรือสาม</p>

พอคุม market แล้ว TSLA ปฏิเสธสมมติฐานว่าทุกวันเท่ากับวันจันทร์ที่ χ²(4) = 17.6, p = 0.001 ส่วน AAPL ที่ p = 0.021 และมี 9 จาก 32 ค่าสัมประสิทธิ์ที่ได้ p < 0.05

เวอร์ชันแรกของโพสต์นี้บอกว่าใช้ Bonferroni ไม่ได้เพราะหุ้นแปดตัวสัมพันธ์กัน **ซึ่งผิด** Bonferroni และ Holm ควบคุม family-wise error rate ได้ภายใต้ dependence *แบบใดก็ได้* ความสัมพันธ์ระหว่างการทดสอบทำให้มัน conservative ขึ้น ไม่ได้ทำให้ใช้ไม่ได้ พอใช้ให้ถูก: เกณฑ์ Bonferroni คือ 0.05/32 = 0.0016 และมีสัมประสิทธิ์ตัวเดียวที่ผ่าน — **TSLA พฤหัส−จันทร์ −87 bps, p < 0.001** ส่วน Holm ซึ่งมี power สูงกว่าเสมอ ก็ปฏิเสธตัวเดียวกันและไม่มีตัวอื่น TSLA ศุกร์−จันทร์ที่ p = 0.0017 พลาดไปนิดเดียว

สิ่งที่ความสัมพันธ์ระหว่างหุ้น*ทำ*จริง ๆ คือกิน power ไป ซึ่งเป็นเหตุผลที่ดีที่จะอยากได้การทดสอบที่ใช้ dependence นั้นแทนที่จะเมินมัน เวอร์ชันแรกมีอยู่อันหนึ่ง: สลับป้ายวันในสัปดาห์แล้ว fit ใหม่ มันพังสามจุด การสลับป้ายทั่วทั้งอนุกรมทำลาย volatility clustering และ autocorrelation ที่ Newey-West มีไว้รับมือ มันเอา t-statistic แบบ classical ไปเทียบกับ null แบบ classical ขณะที่ตารางรายงานค่า HAC และตัวสุ่มเลขเป็น congruential generator ที่ผมเขียนเอง ซึ่งหลังผ่านเลขทศนิยมของ JavaScript กับ mask 31 บิตแล้ว state วนซ้ำทุก 10,466 ค่า — การสลับ 2,512 วันใช้ 2,512 ค่า ดังนั้น "2,000 permutations" จริง ๆ คือการสลับที่ต่างกันราวสี่แบบ ทำซ้ำห้าร้อยรอบ ค่า p = 0.0005 ของมันไม่ได้วัดอะไรเลย

ตัวแทนคือ dependent wild bootstrap: fit หุ้นแต่ละตัว*โดยไม่มี* dummy วัน เก็บค่า fitted กับ residual ไว้ในช่องปฏิทินเดิมของมัน แล้วสร้างตัวอย่างภายใต้ null เป็น fitted + residual × w โดย w คือค่าปกติมาตรฐานหนึ่งค่าต่อบล็อกสิบวันทำการ และ**ใช้ w ชุดเดียวกันกับหุ้นทั้งแปดตัว** วิธีนี้รักษา heteroskedasticity, volatility clustering และความสัมพันธ์ระหว่างหุ้นในวันเดียวกันไว้ และรักษาความสัมพันธ์ตามเวลาไว้ภายในบล็อก จากนั้น fit ใหม่พร้อม dummy บันทึกค่า HAC |t| ที่ใหญ่ที่สุดใน 32 ค่า ทำซ้ำ 4,999 รอบ:

| | max &#124;t&#124; |
| --- | ---: |
| ที่สังเกตได้จริง | 3.96 |
| null median | 2.19 |
| null เปอร์เซ็นไทล์ที่ 95 | 3.05 |
| null เปอร์เซ็นไทล์ที่ 99 | 3.51 |

มี 6 จาก 4,999 รอบที่เกินค่าที่สังเกตได้ family-wise p = **0.0014** Monte Carlo standard error 0.0005 บล็อกยาว 1, 5 และ 20 วันให้ 0.0045, 0.002 และ 0.002 สมมติฐานของ bootstrap เองคือ residual จากโมเดลที่ถูกจำกัดคือ noise ที่ถูกต้อง และตัวคูณแบบ Gaussian ใช้แทนการ resample ได้ มันไม่รู้อะไรเกี่ยวกับสิ่งที่โมเดลละไว้ ภายใต้เงื่อนไขนั้น รูปแบบวันจันทร์ในตัวอย่างนี้ไม่ใช่ noise และโดยเนื้อแท้แล้วเป็นของหุ้นตัวเดียว

## แล้วผมก็ถามว่าวันจันทร์ยาวแค่ไหน

ผลตอบแทนวันจันทร์ของหุ้น คือราคาปิดวันจันทร์หารด้วยราคาปิดวันศุกร์ มันคร่อมวันหยุดสุดสัปดาห์ ขณะที่ผลตอบแทนของวันอื่นคร่อมแค่หนึ่งคืน

```
จันทร์ 3.04 วันปฏิทิน     อังคาร 1.30     พุธ 1.01     พฤหัส 1.01     ศุกร์ 1.03
```

อังคารได้ 1.30 ไม่ใช่ 1.00 เพราะวันหยุดที่ตรงกับวันจันทร์ดันช่องว่างไปโผล่ที่วันอังคาร นี่คือนิยามมาตรฐานของ weekend effect ไม่ใช่ความผิดพลาดในตัวมันเอง งานวิจัยวัด close-to-close ของวันจันทร์แบบนี้มาตลอด แต่มันชวนให้ถามคำถามที่ชอบธรรม: ถ้าหุ้นมี drift ขึ้นตามเวลาปฏิทิน ช่วงสามวันย่อมได้มากกว่าช่วงหนึ่งวัน และ "Monday premium" อาจเป็นแค่นั้น

ความพยายามแรกของผมในการตอบ คือใส่ตัวแปรจำนวนวันปฏิทินที่ผ่านไปตั้งแต่ราคาปิดครั้งก่อน:

| Wald p | base | คุมวันปฏิทิน | winsorize 1% | ตัดหาง 1% | ครึ่งแรก | ครึ่งหลัง |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| NVDA | 0.215 | 0.250 | 0.075 | 0.072 | 0.821 | **0.023** |
| TSLA | **0.001** | 0.122 | **<0.001** | **<0.001** | **0.003** | 0.071 |
| AAPL | **0.021** | **0.004** | **0.034** | **0.039** | **0.001** | 0.387 |
| MSFT | 0.484 | 0.616 | 0.528 | 0.421 | 0.386 | 0.803 |
| AMZN | 0.316 | 0.162 | 0.091 | **0.026** | **<0.001** | 0.790 |
| META | 0.510 | 0.387 | 0.272 | 0.312 | 0.425 | 0.965 |
| GOOGL | 0.906 | 0.391 | 0.734 | 0.267 | 0.311 | 0.997 |
| AMD | 0.065 | 0.788 | **0.050** | **0.045** | 0.160 | 0.660 |

TSLA จาก 0.001 กลายเป็น 0.122 ส่วน AMD จาก 0.065 กลายเป็น 0.788 และเวอร์ชันแรกของโพสต์นี้เรียกสิ่งนั้นว่า effect "คือปฏิทิน" ลองดูว่าอะไรขยับจริง สัมประสิทธิ์พฤหัส−จันทร์ของ TSLA ไปจาก −87 bps เป็น −78 bps — ราวหนึ่งในสิบ — ขณะที่ standard error ของมันไปจาก 22 bps เป็น 49 bps ค่า t ลดเพราะความไม่แน่นอนโตสองเท่า ไม่ใช่เพราะค่าประมาณหด เหตุผลเป็นเชิงกลไก: เมื่อวันจันทร์เป็นฐาน "จำนวนวันปฏิทินลบหนึ่ง" แทบจะเป็น dummy วันจันทร์ในคราบอื่น เอาไป regress บน dummy วันทั้งหลายได้ R² = 0.76 และข้อสังเกตเดียวที่แยกสองตัวนี้ออกจากกันได้คือ 96 วันที่ถูกวันหยุดเลื่อนในตัวอย่าง มี 12 จาก 32 สัมประสิทธิ์ที่พลิกเครื่องหมายหลังคุมปฏิทิน ไม่ใช่ "ส่วนใหญ่" อย่างที่ผมเขียนตอนแรก และ family-wise bootstrap บน specification ที่คุมแล้วให้ p = 0.107 — ซึ่งบอกว่าโมเดลที่คุมแล้วมองไม่เห็นรูปแบบนั้นอีกต่อไป ไม่ได้บอกว่ารูปแบบนั้นคือเวลาปฏิทิน regression ที่มี regressor สองตัวเกือบ collinear ไม่สามารถยกความดีความชอบให้ตัวใดตัวหนึ่งได้ แต่ผมทำไปแล้ว

มันไม่ได้อยู่ตรงนั้น สำหรับ 6 ใน 8 ตัว ขาปิดวันศุกร์→เปิดวันจันทร์เป็นผลตอบแทนข้ามคืนที่*ต่ำที่สุด*ของสัปดาห์ — นั่นคือ weekend effect ในตำรา แบบจาง ๆ และเครื่องหมายถูกต้อง สำหรับทั้ง 8 ตัว ช่วงเปิด→ปิดของวันจันทร์เป็นช่วงซื้อขายที่*สูงที่สุด*ในห้าวัน อะไรก็ตามที่ทำให้ close-to-close ของวันจันทร์สูงในตัวอย่างนี้ มันเกิดขึ้นระหว่าง 9:30 ถึง 16:00 ของวันจันทร์ ไม่ใช่ข้ามสุดสัปดาห์ เรื่องเล่าเรื่อง drift ตามเวลาปฏิทินทำนายตรงกันข้าม ดังนั้นคำอธิบายที่ผมเอาไปตั้งเป็นชื่อเวอร์ชันแรกของโพสต์นี้ ไม่ใช่แค่ไม่ได้ทดสอบ แต่ผิด

ผมอยากระวังในทิศทางตรงข้ามเท่า ๆ กัน ความต่างระดับช่วงซื้อขายมีนัยสำคัญที่ 5% แค่สามตัวก่อนแก้ multiplicity ใด ๆ (NVDA 0.020, TSLA 0.020, AAPL 0.032) ส่วนข้ามคืนไม่มีเลย และนี่คือการแยกเชิงพรรณนาของตัวอย่างเดียว สิ่งที่มันรองรับได้แคบ: effect ตรงที่มี เป็น effect ของช่วงซื้อขายวันจันทร์ และมันไม่ใช่ความผิดพลาดเรื่องหน่วย

## อีกสองข้อที่เช็ค และสิ่งที่มันบอกได้กับบอกไม่ได้

**ค่าสุดขั้ว** winsorize ที่เปอร์เซ็นไทล์ 1 กับ 99 หรือตัดวันที่สุดขั้วที่สุด 1% ทิ้งไปเลย TSLA ยังอยู่ที่ p < 0.001 นั่นบอกว่าผลของ TSLA ไม่ไวต่อการ cap หรือตัดหางที่ระดับนี้ มัน*ไม่ได้*บอกด้วยตัวเองว่าผล "กระจายทั่วกลุ่มตัวอย่าง" อย่างที่ผมเคยอ้าง สำหรับเรื่องนั้นผมทำสิ่งที่ตรงกว่า: fit สัมประสิทธิ์พฤหัส−จันทร์ของ TSLA ใหม่ 2,512 รอบ โดยตัดออกทีละวัน วันเดียวที่มีอิทธิพลสูงสุดขยับ t ไป 0.28 ตัดห้าวันที่มีอิทธิพลสูงสุดพร้อมกัน สัมประสิทธิ์ไปจาก −87 bps (t = −3.96) เป็น −96 bps (t = −4.66) ตัดยี่สิบห้าวันเหลือ −74 bps (t = −3.92) วันที่มีผลมากที่สุดกลับดึง*สวนทาง*กับมัน ตอนนี้ผมพูดได้แล้ว: ผลนี้ไม่ได้ถูกแบกด้วยวันไม่กี่วัน

**ความเสถียร** เวอร์ชันแรกตัดทศวรรษเป็นสองครึ่ง เห็นว่าตัวที่มีนัยสำคัญในแต่ละครึ่งเป็นคนละตัว แล้วเรียกว่า "ไม่ทำซ้ำนอกกลุ่มตัวอย่าง" ผิดทั้งสองท่อน สองครึ่งคือสองชิ้นของกลุ่มตัวอย่างเดียวกันที่ผมเลือกหลังรู้ผล ไม่มีอะไรตรงนี้เป็น out of sample และ "มีนัยสำคัญในครึ่งหนึ่ง ไม่มีในอีกครึ่ง" ไม่ใช่หลักฐานว่าต่างกัน — ความต่างต้องถูกทดสอบ ดังนั้น: regression รวมหนึ่งชุดต่อหุ้น ใส่ตัวบ่งชี้ครึ่งหลังคูณกับ regressor ทุกตัว แล้ว Wald test บนพจน์ interaction ทั้งสี่

คำตอบของคำถามตั้งต้นจึงเป็น: ในตัวอย่างนี้มี Monday-session premium ที่ดูเหมือนของจริง ส่วนใหญ่อยู่ใน TSLA ขนาดของมันไม่ถึงหนึ่งเปอร์เซ็นต์ของผลลัพธ์ DCA หนึ่งทศวรรษ และจุดที่คุณเริ่มกลบมันมิด การเลือกวันในสัปดาห์ไม่ใช่การตัดสินใจที่คุ้มจะมี

## สิ่งที่งานนี้ยืนยันไม่ได้

- **กลุ่มตัวอย่างคือผู้รอดชีวิต** ผมเลือกบริษัทแปดแห่งที่ดังในปี 2026 ทุกตัวเป็นผู้ชนะรายใหญ่ที่ถูกเลือกหลังจากรู้ผลแล้ว ซึ่งบิดเบือนระดับผลตอบแทนอย่างรุนแรง มันคือเหตุผลที่ "วันจันทร์ชนะ" ในตาราง DCA และผมตัดไม่ได้ว่ามันไม่ได้ไปกำหนดโครงสร้างรายวันด้วย
- **นี่คือ exploratory** ตัวอย่างเดียว หั่นหลายแบบ โดยเลือก specification ระหว่างที่มองผลอยู่ ค่า p จาก bootstrap ไม่รู้เรื่องนั้น
- **ราคาปรับ split แต่ไม่ได้ปรับปันผล** สำหรับ AAPL กับ MSFT คือหายไปราวครึ่งเปอร์เซ็นต์ต่อปี และถ้าวัน ex-dividend กระจุกอยู่บางวันในสัปดาห์ มันจะไปลงที่สัมประสิทธิ์ตัวใดตัวหนึ่งแทนที่จะกระจาย
- **ดัชนี market ไม่รวมปันผล** เพราะเป็นระดับดัชนี ไม่ใช่ total return index และไม่มีราคาเปิด การแยกเปิด/ปิดจึงไม่ได้ปรับด้วย market
- **ตลาดเดียว ทศวรรษเดียว บริษัทประเภทเดียว** หุ้นเทคโนโลยี/เติบโตขนาดใหญ่ของสหรัฐแปดตัว ในทศวรรษที่ใจดีกับพวกมันมาก
- **bootstrap รักษา dependence ภายในบล็อกสิบวันและตัดมันที่ขอบบล็อก** และสมมติว่า residual ของโมเดลที่ถูกจำกัดคือ noise บล็อกขนาดต่างกันให้คำตอบเดียวกัน ซึ่งน่าอุ่นใจแต่ไม่ใช่ข้อสรุป

## อยากทำซ้ำ เริ่มจากตรงนี้

ข้อมูลราคาและดัชนีแจกจ่ายต่อไม่ได้ รีโปนี้จึงเก็บสถิติที่คำนวณแล้วกับโค้ดที่สร้างข้อมูลตั้งต้นขึ้นมาใหม่ ไม่ได้เก็บตัวอนุกรม:

```sh
cd analysis/monday-effect
bun run fetch.ts    # ดาวน์โหลดลง ./data ซึ่ง gitignore ไว้
bun run run.ts      # เขียน public/analysis/monday-effect/results.json (ราวสิบนาที)
bun run hero.ts     # สร้างกราฟข้างบนใหม่จากไฟล์นั้น
bun test            # OLS, HAC, tail probability, RNG, Holm, กติกา DCA
```

ทุกตัวเลขในโพสต์นี้ออกมาจาก [results.json](/analysis/monday-effect/results.json) รวมถึงตัวเลขที่ขัดกับเวอร์ชันแรก ส่วน regression, Newey-West covariance, Wald test, หางของ normal กับ chi-square แบบ exact, PRNG และลูป bootstrap รวมกันไม่กี่ร้อยบรรทัด TypeScript ไม่มี dependency และตอนนี้มี test ที่เทียบกับสูตรปิดแล้ว ซึ่งเป็นเรื่องที่ควรรู้ไว้: เครื่องมือตรงนี้เล็กพอที่จะอ่านได้ และการอ่านมันถูกกว่าการเชื่อมัน

มีบั๊กสามตัวที่ขอสารภาพ เพราะทั้งสามยังอยู่ในโค้ดตอนที่ผมกำลังสรุปผล ฟังก์ชันหาหางขวาของ chi-square ของผมตอนแรกคืนค่าหางผิดข้างเมื่ออาร์กิวเมนต์ติดลบ ทำให้ค่า Wald 1.02 ที่ df = 4 รายงาน p = 0.094 แทนที่จะเป็น 0.906 ผมเจอมันเพราะค่า p ขัดกับค่าสถิติที่อยู่ข้าง ๆ แก้แล้วมันก็ยังเป็น Wilson–Hilferty approximation ที่ถูกรายงานสี่ตำแหน่ง ตอนนี้เป็นค่า exact แล้ว และตัวสุ่มเลขเบื้องหลัง family-wise test อันแรกมีคาบ 10,466 ซึ่ง test ของผมไม่มีทางจับได้ เพราะผมไม่มี test ความขัดแย้งภายในที่ควรตั้งใจมองหา ไม่ได้มีแค่ระหว่างค่า p กับค่าสถิติของมัน แต่รวมถึงระหว่างเรื่องเล่าในชื่อโพสต์ กับการที่มีอะไรในโค้ดทดสอบมันจริงหรือเปล่า
